## Request, as given (lightly cleaned up from a dictated message)

1. Add an "Assign All" button to the task assignee section.
2. Add a short note function tied to a task's status (something like "waiting
   on X to connect").
3. Move dependency-connector arrows behind the task bars so bar text isn't
   cut through by an arrow.
4. (Follow-up ask) Title-case the status dropdown labels, and add a new
   "Late" status.

Requests 1 and 2 were ambiguous as dictated — resolved via a clarifying
question before building. See decisions below.

## Decisions made this session

- **Assign All is one-click, not a toggle.** Clicking it checks every member
  onto the task; it doesn't unassign if already all-checked. Mirrors the
  existing "All Team Members" bulk option in Log Time (Time & Cost tab).
- **Status note is a new dedicated field**, not a repurposing of the existing
  task `description` field (which already exists, tucked in the "Time of day
  & notes" `<details>` disclosure). The status note is short, always-visible
  in the task panel right under the Status dropdown, and surfaces as a 📝
  tooltip icon next to the status dot on the task row — visible without
  opening the task panel at all.

## What was built

- **`taskAssignAllBtn`** (index.html, wired in `src/interactions.js`
  `wireTaskPanel`): sets `assigneeIds` to every member's id in one write.
- **`task.statusNote`** (new field, default `''`): text input under the
  Status dropdown in the task panel; renders as a `.status-note-flag` icon
  (title = the note text) next to `.status-dot` in `src/render.js`
  `buildTaskRow`, only when non-empty. Threaded through
  `src/store.js` (`createTask`, `importState` — `updateTaskDoc` needed no
  change since it just merges whatever patch it's given). Old Firestore task
  docs without this field just read as `''` via `task.statusNote || ''`
  fallbacks — no migration/backfill needed.
- **`STATUS_VALUES` / `STATUS_LABELS`** centralized in `src/state.js`.
  Added `'late'` to `STATUS_VALUES`. Labels are now title case ("In
  Progress", not "in progress" or "In progress"). This also deleted a
  **stale, unused duplicate label map** that had been dead code in
  `src/render.js` (wrong casing, missing `late`) — if you're adding another
  status value in the future, `state.js` is now the one place that needs it;
  check there's no second copy drifting elsewhere before assuming that.
- **Late status color**: amber `#f08c00`, added to both `.status-dot.status-late`
  and `.bar.status-late` in `styles.css` (matches the existing
  `.conflict-flag` warning color, semantically close to "overdue").
- **Connector arrows behind bars**: in `index.html`, `#connectorsSvg` now
  comes *before* `#chartCol` inside `.chart-wrap`. Neither element sets an
  explicit `z-index`, so stacking is purely DOM-order-based — whichever of
  the two is later in the markup paints on top. **If `.chart-wrap`'s
  structure gets touched again, keep the svg first** or arrows will draw
  over bar text again. (An explicit `z-index` pair would be more robust than
  relying on DOM order if this ever gets fragile — not done here since it
  wasn't necessary.)
